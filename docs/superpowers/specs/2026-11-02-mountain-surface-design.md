# Блоки на горах: снег, лёд, градиент, трава

Ветка `26.1`, Minecraft 26.1, Lithostitched 1.8.1. Статус: **реализовано, но не собрано** (в этой среде нет Maven, Mojang, Gradle). Сборку и просмотр в игре делает пользователь.

## 1. Цель
Не менять форму гор. Поменять только блоки поверхности в части горных биомов: снег на вершинах, под ним немного льда, ниже градиент камней, на ровных местах трава.

## 2. Требования (слова пользователя)
| Что | Значение |
|---|---|
| Биомы | `meadow`, `stony_peaks`, `windswept_hills`, `windswept_gravelly_hills`, `windswept_forest`, `windswept_savanna`. Заснеженные горы и вершины (`jagged_peaks`, `frozen_peaks`, `snowy_slopes`, `grove`) не трогаем |
| Снег | верхние 10 блоков каждой горы, считая от её вершины |
| Лёд | ниже снега, `blue_ice`, 5 блоков |
| Градиент | ниже льда, снизу вверх: туф, гравий, андезит, камень (камень под льдом), с дизерингом на границах |
| Крутой склон | градиент |
| Ровное место | трава. Градиент после площадки в середине горы продолжается по высоте |
| Ровное в снегу и льду | остаётся снегом и льдом |
| Глубина изменений | 3-4 блока от поверхности |
| Старый `steep_rock_gradient.json` | наше правило идёт первым, старое остаётся для остальных биомов |

## 3. Что я выбрал сам (на ревью, поправь, если не так)
1. Снег это `minecraft:snow_block`.
2. Глубина: 4 блока (`stone_depth` с `offset: 3` даёт верхние 4 блока) для снега, льда и градиента; трава это `grass_block` и под ней 3 блока `dirt`.
3. Ровно: перепад высот до соседей не больше 1 блока. Берём условие Lithostitched `slope`. Оно считает 4 соседей только внутри чанка, на краю чанка сосед равен самой колонке (на границах чанков возможна лишняя «ровность»).
4. Подножие и вершина: минимум и максимум высоты по 48 точкам вокруг клетки 4×4 блока: 3 кольца (радиусы 16, 32, 48) по 16 направлений.
5. Минимальный рельеф: если вершина выше подножия меньше чем на 32 блока, холм слишком низкий, снег, лёд и градиент не ставим (остаётся ваниль). Без этого на холме в 5 блоков весь холм стал бы снегом. Этого порога пользователь не называл.
6. Градиент считается как доля высоты между подножием и линией льда (вершина минус 15): туф до 0.25, гравий до 0.5, андезит до 0.75, камень выше. Доля ограничена `[0, 1]`. Так все 4 слоя видны на любой горе выше минимума.
7. Дизеринг: у каждой границы полоса ±0.05 доли, внутри полосы блок выбирает высокочастотный шум мода `taleks-better-landscape:forest_floor_dither` (`firstOctave: 1`). Границу снега и льда по высоте не дизерим.
8. Вершина считается по грубой оценке `preliminary_surface_level` (ванильная функция роутера шума), а не по готовому рельефу. Расстояние от вершины = `peak - own`, обе величины из одной функции, чтобы не было смещения. Мелкая «рваность» рельефа в снеговую линию не попадает.
9. Трава и снег не ставятся под водой: в правило добавлены `above_preliminary_surface` и `water` (как в `forest_floor.json` автора).

## 4. Подход
Lithostitched 1.8 для 26.1 имеет условия поверхности только `all_of`, `any_of`, `biome`, `slope` (проверено по исходникам снимка «1.8.0 beta 1»; `sample_density` есть только в исходниках 26.2; jar 1.8.1 не смотрел). Условия «высота от вершины горы» нет, поэтому нужно одно своё Java-условие. Всё остальное это JSON в стиле автора мода.

## 6. Как работает `PeakCondition`
1. Условие создаётся на каждый чанк (`apply(context)`). Общее состояние чанка (высоты колонок, замеры клеток) лежит в `WeakHashMap` по ключу `Context`, чтобы 9 условий `peak` в одном правиле мерили каждую точку один раз.
2. Контекст читаем через `dev.worldgen.lithostitched.duck.ContextAccessor` (`getX`, `getZ`, `getRandomState`). Он есть в обязательной зависимости, свой миксин не нужен. Это внутренний API Lithostitched, версию надо держать закреплённой.
3. Высота: `randomState.router().preliminarySurfaceLevel()` в точке `(x, 0, z)`.
4. Для каждой клетки 4×4 считаем `peak` и `foot` по 48 точкам плюс центр. Это 16 клеток × 49 = 784 вычисления на чанк.
5. Любая ошибка внутри условия: возвращаем `false` и один раз пишем ошибку в лог. Блоки остаются ванильными.

## 7. Порядок правил в JSON
Внутри `biome_is` → `above_preliminary_surface` → `water` → `stone_depth` (offset 3, верхние 4 блока):
1. `peak(drop 0..10)`: `snow_block`.
2. `peak(drop 10..15)`: `blue_ice`.
3. `slope [0, 1]`: на верхнем блоке `grass_block`, ниже `dirt`.
4. Градиент по `peak(fraction)`: сверху вниз по границам 0.75, 0.5, 0.25: выше `b+0.05` верхний блок, в полосе шум решает, иначе нижние правила; самый нижний слой `tuff`.
5. Иначе правила проваливаются на ванильные и на старый `steep_rock_gradient`.

## 8. Проверено
- `PeakMathCheck` проходит (`javac`, 3 слоя: кольца, `drop`, `fraction`, границы 0/10/15, клэмпы, `min_relief`, имена режимов).
- Сгенерированный JSON прогнан через маленький интерпретатор: снег до 10, лёд 11-15, снег и лёд на ровном остаются, трава и земля на ровном ниже льда, глубина 4, полосы градиента и дизеринг на всех границах, низкий холм не меняется. Это проверка логики правил, **не игры**.

## 9. Не проверено (риски)
1. **Сборка.** Код написан по исходникам Lithostitched, без исходников Minecraft. Возможны ошибки компиляции: `DensityFunction.SinglePointContext`, `RandomState.router()`, `KeyDispatchDataCodec.of`, `DataResult.error(Supplier)`, `Codec.intRange`.
2. **Access widener.** Первая сборка пользователя упала: Loom 1.18 для 26.1 ждёт `official`, а я скопировал `named` у Lithostitched («Expected official namespace for access widener entry, found: named»). Заголовок исправлен на `accessWidener v1 official`, повторная сборка не проверена. Также неизвестно, достаточно ли `accessible class` для вызова `super(context)` из `LazyXZCondition` (у Lithostitched только эти записи).
3. **Оценка вершины грубая:** снеговая линия может отличаться от видимой вершины на несколько блоков.
4. **Нагрузка:** 784 вычисления функции на чанк. Если генерация замедлится, уменьшить `radius` в JSON.
5. **Lithostitched 1.8.1** мог отличаться от снимка исходников (`ContextAccessor`, сортировка `priority`).
6. `meadow` и `windswept_savanna` мод сам горами не делает (биомные инжекторы только для windswept_hills, windswept_gravelly_hills, windswept_forest, peaks, slopes), снег там только там, где они вырастают высоко.
7. `slope` не видит соседей за краем чанка.

## 10. Вне рамок
Форма гор, лес, пляжи, фэнтези-зоны, старый `steep_rock_gradient.json`, заснеженные биомы, структуры, деревья на траве.

## 11. Скалистые пики (jagged_peaks, stony_peaks, frozen_peaks)

Только поверхность, форма гор не менялась (маска `mountain_mask` общая с windswept, slopes и grove, правка формы задела бы чужие биомы). Существующие `PeakCondition` и `PeakMath` не менялись, новый Java-код не нужен.

**Трава.** В `mountain_blocks.json` ветка «ровно: `grass_block` + `dirt`» теперь стоит под условием `biome_is` из `meadow` и 4 windswept. `stony_peaks` остаётся в общем списке биомов файла (снег, лёд и градиент сохранены), но трава и земля на ровных местах ему больше не ставятся: плато получают обычный градиент туф-гравий-андезит-камень. `jagged_peaks` и `frozen_peaks` в этом файле не было, травы в проекте для них нигде нет.

**Скалы.** Новый `rocky_peaks.json` (`add_surface_rule`, priority 890, раньше `mountain_blocks` 900 и `steep_rock_gradient` 1000), только три биома, верхние 4 блока. Тело горы определяется тремя условиями `peak`: `min_relief` 40 (низкие холмы выпадают), `fraction >= 0.10` (подножие и предгорья выпадают), `drop >= 15.001` (шапка из снега, льда и ванильной поверхности не трогается; у `stony_peaks` она остаётся от `mountain_blocks`).
- `slope >= 2`: всегда голый камень.
- `slope == 1`: камень там, где `peak_rock_cover > -0.05`.
- `slope == 0`: камень только при `fraction >= 0.5` и `peak_rock_cover > 0.14` (редкие выходы), остальное ровное остаётся снегом или ванилью.
- Порода по высоте (`fraction`): выше 0.65 камень + андезит, 0.40-0.65 камень + андезит + туф, ниже гравий + туф + камень. Границы размыты `forest_floor_dither`, пятна пород задаёт `peak_rock_tone`.
- Новые шумы: `worldgen/noise/peak_rock_cover.json` (firstOctave -4), `peak_rock_tone.json` (-3). Пороги подбирались на модели, в игре их нужно подкрутить.

Проверено: все JSON парсятся, ссылки на шумы существуют, `PeakMathCheck` проходит, модель правил (не игра) даёт 0 травы в `stony_peaks`, `jagged_peaks`, `frozen_peaks`, нулевой эффект `rocky_peaks` вне трёх биомов и на холме с рельефом < 40. Не проверено запуском игры и сборкой.
